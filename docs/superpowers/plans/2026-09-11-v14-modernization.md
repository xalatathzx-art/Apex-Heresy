# Последовательная модернизация V14

**Goal:** выполнить согласованный аудит от исправлений до расширяемой автоматизации, сохраняя текущий контент и работу листов.
**Architecture:** вычисления в стандартных фазах Foundry; документные UUID; один исполнитель изменений; единые сервисы правил за существующими листами. Постепенный перенос, без полной переписи.
**Tech Stack:** JavaScript ES modules, Foundry 14.365, Node 24 node:test, Handlebars.
**Spec:** `docs/architecture-audit-v14-2026-09-11.md`, принят пользователем 11.09.2026.

## Ограничения

- Рабочая копия содержит изменения пользователя; сохранять их. Отдельная ветка codex/v14-modernization, резервная копия исходных файлов вне репозитория.
- Не изменять игровой мир миграциями до проверки кода. Не пересобирать открытые базы компендиумов.
- Каждый исправляемый дефект сначала воспроизводить тестом; проверять реальные методы, подменяя только внешние зависимости Foundry.
- Последовательное выполнение в текущей задаче. Никаких публикаций или обещаний полной поддержки книг без проверки правил.

## 1. Надёжность текущей механики — выполняется

- [ ] Состояния: один критерий активности, Set, повторная активация; проверки включённого/disabled/expired и Item-источника.
- [ ] Свойства: точное распознавание Reliable/Unreliable; тесты EN/RU и результат заклинивания.
- [ ] Кровопотеря: одна функция результата, одинаковый порог, token UUID, полный контекст карточки.
- [ ] Resolver: конкретный token/actor UUID; отсутствие токена не подменяет Actor; проверка смены сцены.
- [ ] Сокеты: activeGM, проверка сообщения, сериализация, идентификатор операции, повторный запрос и ошибки.
- [ ] Миграции: один исполнитель, ожидание, отсутствие ложного успеха, повторяемость, world Item packs и synthetic actors.
- [ ] Undo: отказ при конфликте с последующей записью; восстанавливать только согласованный снимок.

Файлы: `script/dark-heresy.js`, `script/automation/*.mjs`, `tests/*.test.mjs`, `tests/helpers/*.mjs`.
Проверка: `node --test tests/*.test.mjs`, `node --check script/dark-heresy.js`.

## 2. Эффекты и Combat

- [ ] Производные данные до final, стандартный обработчик changes; тест priority, phases, reset.
- [ ] Правила подавления Item AE; источник и активность в листе.
- [ ] V14 registry вместо независимого удаления; перенос последствий усталости.
- [ ] Combat subclass, стандартные nextTurn/nextRound, события начала/конца хода, последовательные зависимые эффекты; toxic на endTurn.

## 3. Модели и общий API

- [ ] Типизированные модели игровых данных с совместимостью исходных template.json.
- [ ] Общий контекст бросков/UUID и стабильный API с событиями; листы используют те же функции.
- [ ] Структурированные traits и безопасный переход старого текстового контента.

## 4. Способности и профили

- [ ] Модификаторы с условиями и происхождением; минимальные реальные способности/психосилы.
- [ ] Явная матрица поддержки DH2/BC/OW/RT/DW; отдельные профили только с проверенными правилами.

## 5. Листы и интеграции

- [ ] Переход листов на ApplicationV2 по одному типу с проверкой форм, редакторов, действий, drag/drop.
- [ ] Отображение источника, подавления, сроков эффектов и результата операций.
- [ ] Интеграционные проверки на Foundry 14.365, измерение подготовки документов до оптимизации.

## Журнал

- Исходный syntax check проходит; ранее автоматических тестов игровой логики не было.
- 11.09.2026: в общий `combatRoll` перенесены проверки боезапаса, режима огня и подзарядки; атаки одного предмета сериализуются внутри клиента, магазин перечитывается перед выполнением. Подзарядка хранит бой и раунд одной записью, первый выстрел первого раунда разрешён, следующий раунд заблокирован. Переброс Судьбы не расходует патроны повторно. Отмена preRoll и недееспособность не запускают подзарядку.
- Проверка этой части: 42 теста проходят; `node --check script/dark-heresy.js` проходит. На ядре 14.365 в GMTEST публичный `api.useItem({dialog:false})` возвращает `cancelled/ammunition` для временного персонажа с пустым магазином. Документ существовал только в памяти и удалён из клиентской коллекции после проверки. Миграции в тестовой вкладке отключены.
- Остаётся в этапе 3: структурированные свойства, расширенные проверки API и миграций на копии мира. Локальная очередь атаки не является межклиентной блокировкой; одновременные действия двух владельцев требуют отдельного протокола. Этапы 4–5 ещё не выполнены.
- Следующий шаг этапа 3 реализован: `system.traitOverrides` для weapon/vehicleWeapon/psychicPower, проверяемые типы, API `setItemTraits`, наследование старого текста, изменения модификациями и боеприпасами. Исправлен захват числа соседнего свойства в парсере. Контракт описан в `docs/api-v1.md`. Редактор в листах пока не добавлен. Новая проверка в браузере не выполнена: Playwright потерял сессию, альтернативный Chrome подключился, но localhost:30000 отказал в соединении. Миграции мира не запускались.
- Редактор добавлен отдельной кнопкой в заголовки weapon/vehicleWeapon/psychicPower: native DialogV2, 42 свойства, фильтр, наследование/отключение/значение, точечные патчи и проверка конфликтов. Прежний текстовый picker сохранён. 53 теста проходят. На ядре 14.365 проверены рендер, фильтр, патч без записи в мир, ошибка при потере прав, кнопка листа, свойства временного Actor в атаке и после reset. Сервер снова доступен. Тест миграций старого мира на отдельной копии остаётся открытым.
